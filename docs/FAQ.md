# Frequently Asked Questions

Для упрощения жизни и атмосферы в чате - ответы на некоторые популярные вопросы вынесены сюда.

## Q: На сервере какая-то странная ошибка про `.gitlab-ci.yml`

<details><summary><b>A: [под спойлером]</b></summary>
Перед запуском всех тестов проверяется, что файл `.gitlab-ci.yml` не был изменён.

Для этого дополнительно сравнивается файл `.gitlab-ci.yml` в вашем репозитории и самая последняя версия из публичного репозитория.
Если файлы различаются, то выкидывается ошибка.
Возникнуть она может даже если вы не меняли файл, но в публичном репозитории он обновился.

Решение очень простое – подтяните изменения из публичного репозитория:

```shell
git pull upstream main
```

После этого вам нужно влить изменения в свой репозиторий на gitlab:

```shell
git push origin main
```

Если после пуша какая-то задача не была протестирована, это значит, что в запушенных коммитах её код решения не менялся (система тестирует только такие задачи).
Внесите в него минимальные изменения (e.g. допишите комментарий), закоммитьте и запушьте их (потом откатите их, если хотите).
</details>

## Q: На сервере какая-то странная ошибка про `tempdir`/`tempfile`

<details><summary><b>A: [под спойлером]</b></summary>

Скорее всего ошибка не у вас, а просто закончилось место на серваке. Для этого призовите в чатике админа курса и он всё исправит.
После этого достаточно просто перезапустить джобы.

## Q: gitlab pipeline упал, но задачка точно сделана верно

<details><summary><b>A: [под спойлером]</b></summary>

* Откройте и внимательно прочитайте логи в gitlab pipeline
  (нужно нажать на красную кнопку `failed` в упавшей джобе и откроются логи)
* Если тестируется несколько задач, то job будет падать если хоть одна из них упала.
  НО: Для всех успешно проверенных задачек баллы будут выставлены независимо от остальных
* Если задачка одна, но падает и нет никаких ошибок, то.. Почитайте логи ещё раз
* Если в логах написано, что баллы выставлены, но их точно нет - баг репортьте в чат, тегая админа
  (и сразу описывая что именно упало и прикрепляя ссылку на пайплайн)

</details>

## Q: Проверки(clang-tidy/clang-format) локально run_linter.sh и на сервере не совпадают

<details><summary><b>A: [под спойлером]</b></summary>

На сервере запускается скрипт ```run_linter.sh```. Причина не совпадения может быть, что у вас старая
версия ```clang-tidy``` и ```clang-format```.

```shell
# Эта проверка вашей стандартной версии clang-tidy
clang-tidy --version
# Эта проверка установлен ли clang-tidy-18
clang-tidy-18 --version
```

* Для установки в консоль введите следующие команды, чтобы установить актуальную (18) версию
    ```clang-tidy``` и ```clang-format```.

    ```shell
    wget https://apt.llvm.org/llvm.sh
    chmod +x llvm.sh
    sudo ./llvm.sh 18 all
    ```

* Когда у вас установлен ```clang-tidy-18```, но используется стандартный другой версии ```clang-tidy```.

    ```shell
    sudo rm -rf /usr/bin/clang-format && sudo ln -s /usr/bin/clang-format-18 /usr/bin/clang-format && clang-format --version
    sudo rm -rf /usr/bin/clang-tidy && sudo ln -s /usr/bin/clang-tidy-18 /usr/bin/clang-tidy && clang-tidy --version
    ```

</details>

## Q: CLion. Error reading from .clang-format: Invalid argument - unknown key '...'

<details><summary><b>A: [под спойлером]</b></summary>

К сожалению, самые новые опции ClangFormat не поддерживаются CLion, например,

```shell
AlignConsecutiveShortCaseStatements
```

. Данная опция будет поддерживаться только в следующих релизах
CLion. Из-за особенностей реализации плагина ClangFormat в CLion, если произошла ошибка, то никакие
настройки из ```.clang-format``` не применяются и автоформатирование может работать некорректно.

В данной ситуации рекомендуется запускать скрипт ```run_linter.sh``` [инструкции](../docs/SETUP.md) и исправлять ошибки в
соответствии с выводом этого скрипта.

</details>

## Q: Фикс странных ошибок при запуске run_linter.sh

<details><summary><b>A: [под спойлером]</b></summary>

Пример таких ошибок: не найдены стандартные `include` из ```std```, методам класса, объявление которых уже было написано в файле `.h` просит добавить еще какие-либо ключевые слова вроде `static`

Проблема заключается в том, что в системе отсутствует стандартная либа GNU C++.

Решение:
Устанавливаем пакет стандартной библиотеки командой `sudo apt install libstdc++-12-dev`. Вместо нее можно поставить 13 версию, она сейчас последняя.

</details>

## Q: Установка правильного clang и clang++ на macOS

<details><summary><b>A: [под спойлером]</b></summary>

По умолчанию на macOS нет `clang`.

В рамках данного курса необходимо использование `LLVM Clang 18.0.0` и выше. Для установки LLVM Clang необходимо сделать следующее:

```bash
brew install llvm
```

Clang и Clang++ будут находится по следующим путям:

```bash
/opt/homebrew/opt/llvm/bin/clang
/opt/homebrew/opt/llvm/bin/clang++
```

Возможно, у Вас будет другой префикс у строк выше, в таком случае стоит получить его с помощью `brew --prefix llvm`.

Проверьте, что у Вас установлен Homebrew clang с помощью команды clang --version. Пример вывода:

```bash
Homebrew clang version 18.0.1
Target: arm64-apple-darwin23.0.0
Thread model: posix
InstalledDir: /opt/homebrew/opt/llvm/bin
```

Если Clang не стал автоматически доступен попробуйте перезапустить терминал. Если нет, то добавьте директорию в бинарными файлами в PATH:

```bash
PATH="/opt/homebrew/opt/llvm/bin:$PATH"; export PATH;
```

При наличии Xcode и Xcode Command Line Tools

Если Вы пытались заниматься разработкой на macOS с помощью Xcode, скорее всего у Вас установлены Xcode Command Line Tools, которые включают clang (сейчас `Apple Clang 15.0.0`) и другие утилиты. Скорее всего у Вас возникнут проблемы с тем, что по умолчанию будет использоваться Apple Clang, который, например, не поддерживает `std::format`. Для решения этой проблемы Вам необходимо руками указать Clang и Clang++ в вашей IDE и настройках или CMake:

```bash
/opt/homebrew/opt/llvm/bin/clang
/opt/homebrew/opt/llvm/bin/clang++
```

</details>
